# 棋术大师 APP 全量需求与任务规划整合版

## 文档说明

本文档为全量整合版，覆盖业务需求、产品需求、任务分级规划、项目文档体系、接口规范、GPT-6 开发提示词、全棋种规则边界七大核心模块；**无时间排期，仅按依赖关系划分任务阶段与层级**，完全适配 Android Studio/IDEA/PyCharm/VSCode 全工具链，可直接用于审核与落地执行。

## 一、业务需求文档（BRD）

### 1.1 产品定位

《棋术大师》是一款**纯单机离线**的横屏综合棋类对战 APP，覆盖经典职业棋类与兰州本地化特色棋类，搭载业界顶级开源职业级 AI 引擎，配套海量分级残局库与多模式玩法，面向个人自用场景，主打「解闷挂机 + 棋力提升」双重价值，无需联网、无广告、无内购，全功能本地运行。

### 1.2 核心目标

1. **规则完整度**：全棋种 100% 覆盖官方规则 + 兰州本地特色规则，边界无遗漏
2. **AI 棋力梯度**：实现从纯新手到准职业级的四级平滑梯度，大师难度具备职业级对弈水平
3. **内容丰富度**：残局总量 9000+，覆盖多主题多类型，支撑长期游玩不重复
4. **玩法可玩性**：12 + 种对局 / 闯关 / 趣味玩法，搭配自动化演局，满足解闷、训练、挂机多场景
5. **体验流畅性**：安装包体量 200-300MB，主流机型流畅运行，AI 走子无明显延迟
6. **纯单机约束**：零联网权限、无账号系统、无第三方依赖，所有数据本地存储

### 1.3 目标用户

- 核心用户：象棋 / 围棋 / 麻将爱好者，有日常对弈、残局训练需求
- 本地用户：兰州及西北区域用户，有本地化麻将、民间棋玩法需求
- 进阶用户：希望通过职业级 AI、经典残局提升棋力的业余高手
- 休闲用户：以自动演局、趣味玩法打发时间的轻度玩家

### 1.4 业务范围

表格

| 分类 | 包含内容 |
| --- | --- |
| 覆盖棋种 | 中国象棋、围棋、国标麻将、兰州麻将、兰州方棋、老虎吃羊棋 |
| 核心模式 | 普通人机对战、AI 自动演局、残局闯关、新手教程、棋谱管理 |
| 扩展玩法 | 限时挑战、连胜模式、盲棋模式、自由摆局、棋力评测、每日残局 |
| 成长体系 | 段位等级、星级积分、成就徽章、人物解锁 |
| 边界约束 | 纯单机运行，无真人对战、无联网功能、无云同步、无内购广告 |

### 1.5 核心约束

- 技术栈约束：完全复用现有环境（Android Studio + Java/Kotlin + NDK C++ + Python + Node.js）
- 体量约束：安装包体积 200-300MB，优先保证棋力与内容，不做极致裁剪
- 性能约束：大师级 AI 单步走子≤2s，普通对局流畅不卡顿，支持后台挂机
- AI 约束：仅使用成熟开源职业级引擎，不自研核心对弈算法，保证棋力可靠

### 2.2 页面规划与交互规则

#### 2.2.1 全局页面结构

共 7 个一级页面，采用单 Activity + 多 Fragment 架构，全局左侧返回导航，支持侧滑返回。

#### 2.2.2 首页规划与交互

**布局规则**：固定左右分栏结构

- **左侧区域（40% 屏宽）**：垂直展示玩家人物形象
  - 初始默认国风人物，随段位提升解锁 6 套外观，实时展示当前段位形象
  - 人物下方展示：当前段位、总胜场数、当前星级 / 积分
- **右侧区域（60% 屏宽）**：纵向卡片式布局，排列 5 张玩法入口卡片
  - 卡片对应：中国象棋、围棋、国标麻将、兰州麻将、兰州特色棋
  - 卡片展示信息：棋种名称、玩法简介、已解锁最高难度、残局最高通关数
- **交互规则**：
  1. 点击卡片弹出二级选择面板，选项包含「普通对局」「残局闯关」「新手教程」「扩展玩法」
  2. 选择模式后弹出难度选择框，未解锁难度显示锁定状态与解锁条件
  3. 长按卡片可快速进入上次游玩的模式与难度

#### 2.2.3 对局页面规划与交互

**布局结构**：顶部栏 + 中央棋盘区 + 底部功能栏

- **顶部栏**：当前棋种、难度等级、对局时长、返回主页按钮、设置按钮
- **中央棋盘区**：居中自适应展示棋盘 / 牌桌，支持双指缩放，落子 / 出牌有反馈动画
- **底部功能栏**：悔棋、走子提示、认输、重新开始、切换「手动 / 自动模式」、调速按钮
- **交互规则**：
  1. 默认玩家先手，可在设置中切换为 AI 先手；支持让子 / 让牌自定义
  2. 「自动模式」：双方均由 AI 操控，支持 0.5x-4x 无级调速、暂停、自动续局开关
  3. 悔棋次数按难度限制：简单不限、中等 3 次、困难 1 次、大师不可悔棋
  4. 走子提示按难度分级：简单高亮所有可走位置、中等提示最佳落点、困难 / 大师无提示

#### 2.2.4 残局闯关页面规划与交互

**布局结构**：顶部章节导航 + 关卡网格列表 + 底部进度栏

- **章节分级**：简单篇、中等篇、困难篇、大师篇，未解锁章节显示锁定
- **关卡展示**：网格排列关卡图标，已通关显示对勾，当前关卡高亮
- **交互规则**：
  1. 通关前一关自动解锁下一关，通关当前章节全部关卡解锁下一难度章节
  2. 点击关卡进入残局对局，达成胜利条件即为通关，首次通关奖励星级 / 积分
  3. 支持主题筛选：按杀法、死活、牌型等主题筛选对应残局

#### 2.2.5 新手教程页面规划与交互

- 分棋种设置独立教程，内容包含：规则图文讲解、交互式分步练习、知识点小测试
- 教程通关后解锁对应棋种的「简单难度」，未完成教程默认锁定对局功能
- 支持跳转到对应练习残局，边学边练

#### 2.2.6 其他页面规划

1. **棋谱页面**：分类展示全部对局 / 精彩收藏 / 残局棋谱，支持步进回放、快慢放、导出
2. **个人中心页面**：展示段位、总数据统计、分棋种数据、成就徽章、人物形象管理
3. **设置页面**：难度默认设置、自动续局开关、音效开关、对局时长设置、数据备份 / 恢复

#### 2.2.7 全局交互规则

- 所有对局支持后台挂机，熄屏不暂停，返回前台自动同步进度
- 所有操作有即时反馈，非法操作有明确提示
- 数据自动保存，退出对局 / 关闭 APP 不丢失进度

### 2.3 核心系统规则

#### 2.3.1 AI 四级难度体系

全棋种统一四级难度，采用渐进式解锁，保证新手友好到职业级的平滑过渡。

表格

| 难度等级 | 解锁条件 | 棋力定位 | 核心限制 |
| --- | --- | --- | --- |
| 简单 | 完成新手教程 | 纯新手级 | 搜索深度浅，高概率随机走法，只走基础棋理，悔棋 / 提示无限制 |
| 中等 | 简单难度累计胜 10 场 | 业余入门级 | 中深度搜索，少量随机失误，具备基础攻防意识，单局 3 次悔棋 / 提示 |
| 困难 | 中等难度累计胜 15 场 | 业余高手级 | 较深搜索，几乎无失误，熟练掌握定式与残局技巧，单局 1 次悔棋 / 提示 |
| 大师 | 困难难度累计胜 20 场 | 准职业级 | 满深度搜索，最优策略，职业级棋力，不可悔棋 / 无提示 |

#### 2.3.2 残局闯关系统

1. **关卡体量**：全棋种共 9000 + 关，按难度分为 4 档，每档按主题分类
2. **解锁规则**：线性解锁，通关前一关解锁下一关；通关当前难度全章节解锁下一难度
3. **关卡类型**：
   - 主线关卡：古今经典残局，由易到难递进
   - 主题关卡：按专项技巧分类（如象棋连将杀、围棋死活题、麻将牌型题）
   - 每日残局：每日更新一道精选关卡，打卡累计成就
   - 随机挑战：随机抽取对应难度残局，不限次数冲关
4. **通关判定**：玩家执指定方，达成胜利条件即为通关；支持重置关卡
5. **奖励规则**：首次通关奖励对应星级 / 积分，重复挑战无奖励

#### 2.3.3 等级成长体系

三套升降级规则并行，满足任意一种即可升级，降级规则同步对应。

1. **胜场数达标制**：累计赢下对应数量对局即可升级，难度不限
2. **星级升降制**：赢 1 场 + 1 星，输 1 场 - 1 星；星级满额自动升级，星级扣完降一级；每段需 5 星
3. **难度积分制**：
   - 赢场得分 = 难度系数 × 基础分（基础分 10 分）
   - 输场扣分 = 难度系数 × 基础分 × 2（翻倍扣分）
   - 难度系数：简单 = 1，中等 = 2，困难 = 4，大师 = 8
   - 积分达到阈值自动升级，低于当前段位阈值自动降级

#### 2.3.4 自动化对局系统

针对挂机解闷场景深度优化：

- 支持 AI vs AI 全托管自动对弈，玩家可旁观
- 0.5x-4x 无级调速，支持单步停顿自定义
- 自动续局开关：开启后一局结束自动开下一局，可设置最大连开局数
- 指定开局功能：可加载固定棋谱 / 牌型作为开局，自动演后续变化
- 精彩局自动保存：可设置触发条件（逆转、大师级对局、超长局），满足条件自动存为棋谱
- 后台挂机优化：后台运行自动降频，降低功耗与资源占用

### 2.4 各棋类玩法规则与边界明细

#### 2.4.1 中国象棋

**基础规则**：严格遵循中国象棋官方竞赛规则

- 10 行 9 列标准棋盘，双方各 16 枚棋子，轮流走子，将死对方将 / 帅为胜利
- 行棋准则：马走日、象走田、车走直线、炮翻山、士走斜线、将帅不出九宫、兵卒过河可横走

**规则边界**：

- 长将、长捉、长拦等重复局面，直接判定进攻方负
- 困毙（己方无棋可走）判定本局负
- 将帅直接对面判定主动方负
- 支持自定义对局时长，超时判负；默认无时限
- 和棋需双方满足局面条件，单方面不可强制和棋
- 支持悔棋、提和、认输操作

#### 2.4.2 围棋

**基础规则**：遵循中国围棋协会竞赛规则（数子法）

- 默认 19 路棋盘，支持 9 路、13 路切换，黑白双方轮流落子，围地面积多者为胜
- 吃子规则：无气棋子立即提掉，禁止全局同形再现（打劫规则）

**规则边界**：

- 禁着点：落子后己方棋子无气且无法提掉对方棋子的位置，禁止落子
- 打劫规则：提劫后必须在别处走一手，方可回提
- 终局判定：双方连续停手后按中国规则数子，黑棋贴 3 又 3/4 子
- 支持 2-9 子让子设置，让子局黑棋不贴目
- 终局支持点目、数子两种结算方式切换

#### 2.4.3 国标麻将

**基础规则**：遵循国家体育总局审定的《麻将竞赛规则》

- 144 张完整牌组（万、条、筒、字牌、花牌），标准推倒胡规则，8 番起胡
- 完整支持吃、碰、杠、听、胡流程，按牌型番数计算得分

**规则边界**：

- 相公（多牌 / 少牌）本局失去胡牌资格
- 炸胡（不符合胡牌条件宣布胡牌）判定本局负，扣除双倍基础分
- 杠上开花、海底捞月、七小对、十三幺等牌型番数严格按国标计算
- 牌墙摸完无人胡牌为流局，不计胜负，下局连庄
- 支持坐庄、连庄规则，庄家输赢翻倍

#### 2.4.4 兰州麻将（本地特色规则）

**基础规则**：兰州本地通用推倒胡玩法（素麻将）

- 108 张牌（仅万、条、筒，无字牌、无花牌），4 人对局，玩家默认坐庄
- 核心特色规则：
  - 刮风下雨：明杠为「刮风」，其余三家各付 1 倍底分；暗杠为「下雨」，其余三家各付 2 倍底分
  - 杠上开花：开杠后摸牌直接胡牌，番数翻倍
  - 报听：听牌后可选择报听，报听后不可换牌，胡牌番数翻倍
  - 捉老鼠：胡牌时最后一张为牌墙最后一张，额外加 1 番

**规则边界**：

- 必须缺一门才可胡牌（万、条、筒最多保留两门）
- 不支持吃牌，仅可碰、杠
- 牌墙摸完无人胡牌为黄庄，庄家轮换，不计胜负
- 炸胡需赔付其余三家，按当前牌型最大番数计算
- 支持自摸、点炮胡牌，点炮由点炮者单独赔付

#### 2.4.5 兰州方棋（俗称「下方」）

**基础规则**：7×7 交叉点棋盘，双方各 14 枚棋子，开局摆满己方两行 + 中间点位

- 双方轮流沿线走一步，己方 4 枚棋子围成正正方形（「成方」）即可吃掉对方任意 1 子
- 吃光对方全部棋子，或使对方无法走子即为胜利

**规则边界**：

- 成方必须是正方向的四个交叉点，斜向连成的方形无效
- 一步同时形成多个方，可对应吃掉对方多枚棋子
- 禁止重复走相同局面形成循环
- 棋子只能沿线走一步，不能跳步

#### 2.4.6 老虎吃羊棋

**基础规则**：专用山形棋盘，一方执 2 只「老虎」，一方执 22 只「羊」

- 老虎方：沿线走步或跳吃，跳过相邻空位的羊即可吃掉，支持连跳连吃
- 羊方：只能沿线走步不能吃子，以完全围堵老虎使其无法移动为胜利

**规则边界**：

- 老虎只能直线走步或跳吃，不能斜向移动
- 羊方开局先摆满己方点位，摆满后双方轮流走步
- 老虎被完全围困无法移动则羊方胜；羊被吃到不足 8 只则老虎方胜
- 老虎不能连续重复跳吃同一位置形成循环

## 三、任务分级规划（按依赖阶段划分・无排期）

按前置依赖关系分为 4 个阶段，每个阶段内分**一级任务（模块级）、二级任务（子模块级）、三级任务（执行项级）**，自上而下逐层拆解，前一阶段全部完成后方可进入下一阶段。

### 3.1 阶段一：基础前置任务

**核心目标**：搭建开发环境、工程框架与统一规范，为后续开发提供底座

表格

| 一级任务 | 二级任务 | 三级任务 |
| --- | --- | --- |
| 1. 开发环境搭建 | 1.1 安卓开发环境配置 | 配置 Android Studio、NDK、CMake、Gradle 版本配置 Kotlin+Jetpack Compose 开发环境配置签名与打包环境 |
|  | 1.2 配套工具环境验证 | 验证 Python 环境与依赖库（NumPy、Pandas）验证 Node.js 环境与工具链配置 VSCode C++ 开发与调试环境 |
| 2. 工程框架搭建 | 2.1 安卓工程初始化 | 创建 Android 项目，配置工程结构与依赖集成 Jetpack Compose、Navigation、Room 数据库配置混淆、压缩、打包基础配置 |
|  | 2.2 C++ 引擎工程搭建 | 搭建 CMake 工程，配置 NDK 交叉编译参数实现基础工具类、数据结构、内存管理配置编译优化选项与架构适配 |

## 五、核心接口文档规范

### 5.1 C++ 引擎层统一接口规范

所有棋种规则引擎与 AI 引擎继承同一抽象基类，保证上层调用无差别。

```
// 走法数据结构
struct Move {
    int fromX;
    int fromY;
    int toX;
    int toY;
    int score; // 评估分数
};

// 游戏结果枚举
enum GameResult {
    GAME_ONGOING = 0,  // 进行中
    FIRST_PLAYER_WIN = 1, // 先手胜
    SECOND_PLAYER_WIN = 2, // 后手胜
    DRAW = 3  // 和棋/流局
};

// 规则引擎基类
class RuleEngineBase {
public:
    // 初始化棋局
    virtual void init() = 0;
    // 执行一步走法，返回是否成功
    virtual bool makeMove(const Move& move) = 0;
    // 悔一步棋
    virtual bool undoMove() = 0;
    // 获取所有合法走法
    virtual std::vector<Move> getLegalMoves() = 0;
    // 检查游戏结果
    virtual GameResult checkGameResult() = 0;
    // 序列化局面为二进制数据
    virtual std::vector<uint8_t> serialize() = 0;
    // 反序列化加载局面
    virtual bool deserialize(const std::vector<uint8_t>& data) = 0;
    // 获取当前玩家
    virtual int getCurrentPlayer() = 0;
};

// AI引擎基类
class AIEngineBase {
public:
    // 初始化AI，设置难度等级 0-3 对应简单-大师
    virtual void init(int difficulty) = 0;
    // 传入当前局面，计算最优走法
    virtual Move getBestMove(const RuleEngineBase* engine) = 0;
    // 设置思考时间限制（毫秒）
    virtual void setTimeLimit(int ms) = 0;
    // 释放AI资源
    virtual void release() = 0;
};
```

### 5.2 JNI 桥接层接口规范

Java 层通过 JNI 调用原生引擎，包名统一为`com.chess.master.engine`。

表格

| JNI 函数 | 功能说明 | 参数 | 返回值 |
| --- | --- | --- | --- |
| nativeInitEngine | 初始化指定棋种的规则引擎 | int gameType（棋种编码） | long（引擎句柄） |
| nativeMakeMove | 执行一步走法 | long engineHandle, Move move | boolean（是否成功） |
| nativeGetLegalMoves | 获取所有合法走法 | long engineHandle | Move[] |
| nativeCheckGameResult | 检查游戏结果 | long engineHandle | int（结果编码） |
| nativeSerialize | 序列化局面 | long engineHandle | byte[] |
| nativeDeserialize | 反序列化加载局面 | long engineHandle, byte[] data | boolean |
| nativeInitAI | 初始化 AI 引擎 | int gameType, int difficulty | long（AI 句柄） |
| nativeGetBestMove | 获取最优走法 | long aiHandle, long engineHandle | Move |
| nativeReleaseEngine | 释放引擎资源 | long engineHandle | void |
| nativeReleaseAI | 释放 AI 资源 | long aiHandle | void |
