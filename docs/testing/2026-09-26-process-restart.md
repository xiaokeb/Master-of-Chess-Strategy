## 故障记录

1. 首版主机脚本使用 PowerShell 不接受的带下划线数字，解析即失败，未操作设备；改为普通整数。
2. `adb exec-out` 在目标收据尚不存在时没有传播远端 cat 失败状态，导致把错误文本当 JSON。改用 shell-v2，检查真实退出码后解析。
3. 限时扩展入口不是滚动容器，夹具错误调用 `performScrollTo`；核对已有导航测试和布局后改为直接点击，限时设置内部仍正常滚动。已通过的自动、人机两组未重跑。
4. 限时 resume 已完成后，下一次 ADB 客户端无法连接本地 5037，verify 日志为空、stderr 明确连接超时，原启动句柄已退出。确认 ADB 再次可达及原检查点仍在，仅用同一 runId 补跑 verify，没有清空数据库或重做超时棋局。补验通过，并核对三份收据的不同 PID、同一棋局和不变棋谱时间。

本轮失败均发生在脚本/测试操作或 ADB 传输；没有通过修改产品行为绕过断言。脚本现会同时显示 stdout/stderr 便于辨别启动失败。

## 安全与剩余边界

- 必须显式传入 `-AllowEmulatorDataReset`，只清空选定模拟器的本项目测试数据，不能自动恢复；真机被拒绝。项目文件、其他应用和真机未修改。
- 两次终止之间不卸载 APK；不以 Activity 重建、导航重进或内存数据库模拟进程死亡。执行与补验方法见 `tools/android/README.md`。
- 此次终局重启点在存档/棋谱/成绩已提交后，证明重复恢复不重复结算；**没有覆盖终局各写入之间被终止的全部窗口**，这是下一项数据一致性检查。
- SIGKILL 验证不依赖 onDestroy 的突发终止恢复；它不是内存压力发生器，不宣称覆盖全部系统回收策略。
- 真机音效、触控体验、长期挂机/功耗和系统重启仍须单独验收。后台整体仍为进行中，象棋也未完成全范围验收。

平台依据：[Android 进程生命周期](https://developer.android.com/guide/components/activities/process-lifecycle)（系统终止不保证 onDestroy）、[命令行设备测试](https://developer.android.com/studio/test/command-line)（独立 instrumentation 启动）。
