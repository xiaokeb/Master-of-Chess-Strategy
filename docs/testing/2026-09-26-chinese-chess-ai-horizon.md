# 象棋 AI 搜索末层困毙修复

## 缺陷与修改

局面 `3k5/9/9/9/9/9/5r3/9/4K4/9 b - - 0 1` 中，黑方可走安静着迫使红帅在两个纵向落点中选择，再用车封锁，第三个半回合即困毙获胜。

旧困难 AI 选择车 `(5,6)→(4,6)` 将军，遗漏搜索范围内的强制胜局。原因是 `search_score` 在深度归零时只检查“被将军且无合法着”，把未被将军的困毙当作普通子力局面。中国象棋困毙应判无合法着一方负。

现改为在预算内的叶节点统一检查是否存在合法着；扫描找到首个合法着立即停止。终局使用原有胜负评价，搜索深度、候选窗口、节点上限和解锁规则不变。预算耗尽的静态评价边界未在本次重构。

## 回归证据

- 先添加 C++ 黑盒测试，旧实现明确在 `can_stalemate` 断言失败；修复后完整原生象棋测试在 AVD 退出码 0。
- C++ 测试同时覆盖原局面及旋转棋盘、互换颜色后的红方局面。要求每个对手应着之后都有一步困毙胜着，并断言对手未被将军、无合法着；不锁死某个同分首着。
- 搜索前后序列化完全一致，验证搜索不污染实际棋局。
- JNI 增加同局面端到端用例，包含选择、应用、逐应手验证和撤销。正式 Gradle 打包后 AVD XML 为 **6/6，0 失败、0 错误、0 跳过**。
- NDK ARM64、x86_64 两个 ABI 构建，App Debug APK 构建，`verifyPikafishNetwork`、`verifyBundledLegalDocuments` 均通过。调试打包有未剥离原生符号提醒，不作为 Release 体积验收。
- 本次不改 UI、音效或 Kotlin 业务逻辑，不重复运行全量界面回归。新的搜索行为仍需后续全棋种验收，不将本用例等同于棋力分级完成。

| 困难 / 中等 | 8 / 1 / 1 / 2 | 85% | 251.36 / 489.12 |

复测另存为 `results/2026-09-26-ai-easy-medium-horizon-v1.jsonl` 和 `results/2026-09-26-ai-medium-hard-horizon-v1.jsonl`，合计 2558 次搜索，不覆盖旧基线。Conda 审核覆盖全部五份报告，11/11 回归通过。计时期间有 Gradle/JNI 验证并行，本数据只作开发观察，不能用小幅耗时变化断言性能升降。

大师旧基线对困难 12 胜，明显未达到相邻档约 7:3 的目标。下一阶段先扩大独立开局样本，再校准梯度，不能靠遗漏合法终局来降低 AI 棋力。
