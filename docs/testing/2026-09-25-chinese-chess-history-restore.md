# 中国象棋 MOCX 历史恢复验证

## 问题与修正

原实现仅检查 CRC32 和历史记录前后棋子占位。把正常兵步的起点改为斜前一格并重新计算 CRC32 后，反向重建仍能成功，实际却违反兵的走法。先添加了在 Android AVD 上失败的回归用例，再让恢复流程从反向重建出的初始局面逐着执行正式合法走法检查，并核对行棋方、被吃子、自然限着计数；已记录的终局、将帅被吃或自然限着达到上限后不得续走。额外改写自然限着计数并重算 CRC32 的测试也被正确拒绝。

NDK LLVM 构建的完整 C++ 象棋规则测试在 Pixel_7_Pro x86_64 AVD 执行退出码 0。最终代码的 App 设备测试 46/46、JNI 设备测试 3/3、Debug APK 构建均通过；同轮 JVM 183/183、Lint 0 错误及 3 条依赖升级提醒。CRC32 是损坏检测而非身份认证；本修正针对不可能的历史局面，不保证导入文件的真实来源。

## 终局结果后续校验

另发现：只改 MOCX 历史裁定字段为“和棋”并重算 CRC32，旧恢复流程会错误结束仍在进行的对局。无历史和有一步合法兵步两类原生用例先失败，修正后引擎对有效历史按当前规则重算裁定；既有长将终局恢复回归仍通过。
