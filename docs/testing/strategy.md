# 测试策略

测试按风险和语言边界分层：

- Kotlin 公共模型与状态转换使用 JVM 单元测试。
- C++ 平台无关规则使用指定 NDK LLVM 构建 Android 测试目标，不调用 MinGW。
- JNI 使用 Kotlin 故障降级单元测试、NDK 编译和少量设备集成测试。
- Compose 只为真实交互流程增加 UI 测试，不为静态排版堆积用例。
- 具体棋种重点覆盖官方规则分支、边界局面、序列化往返和历史回归。

新增行为先运行一个能够证明需求的失败测试，再写最小实现。开发期间只运行相关模块；大节点结束执行一次完整门禁，修复后再执行一次最终门禁。没有设备或 AVD 时，C++ 测试以 Android 目标编译和链接成功作为当前门禁，运行结果保持未执行。

测试报告必须区分“通过”“失败”“仅编译”和“因设备或外部条件未执行”。
