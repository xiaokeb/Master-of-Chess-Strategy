# 象棋残局候选题型扩展（待审）

旧生成器默认以红方车、马、兵及可选炮构造一/两步胜法，容易集中在车杀。离线 `mocs_generate_xiangqi_mates` 现增加第 5 个可选参数 `family`：`classic`（默认，保留既有种子输出）、`rook-horse`、`rook-cannon`、`horse-cannon`、`double-rook`。新题型仍由原生规则枚举唯一首着；两步题须证明所有防守应手，预算耗尽不得冒充证明。显式题型写入候选头，Conda 暂存工具同时校验整批题型一致、子力库存与标注吻合。它只提升候选来源多样性，不自动发布关卡，也不改变已有 16 关。

受影响范围：`engine-native/src/main/cpp/tests/generate_xiangqi_mates.cpp`、`tools/python/stage_xiangqi_candidates.py` 及其专项测试。NDK 30 LLVM x86_64 目标编译链接通过；Conda `MasterofChessStrategy` 暂存专项 11/11、全 Python 离线回归 52/52 通过。Pixel_7_Pro AVD 用旧参数 `1 3 10000 20261001`、`2 2 20000 20261001` 重生的一步/两步流，与既存原始文件 SHA-256 均逐字节相同；新版审核器亦保留其 `staged-not-published` 结果。未知题型参数在模拟器被拒绝。

首次设备生成发现车炮组合附加的马成为实际胜着，与题型目的不符，故收紧新组合：车炮仅一车一炮，双车仅两车；马炮允许第二匹马。审核器对显式题型核对各进攻棋子数量并拒绝额外棋子。收紧后在 AVD 以固定种子分别生成、Conda 独立浅层穷举复核如下。每批均为 1 道、`staged-not-published`，未加入 APK：

| 题型 | 一步：种子/尝试/主着/遍历节点 | 两步：种子/尝试/首着/遍历节点 |
| --- | --- | --- |
| 车炮 | `20261002 / 0 / 炮 (3,4)→(5,4) / 65` | `20261003 / 4 / 炮 (5,8)→(3,8) / 1982` |
| 马炮 | `20261002 / 1 / 马 (6,3)→(7,1) / 57` | `20261003 / 17 / 马 (3,5)→(4,3) / 746` |
| 双车 | `20261002 / 2 / 车 (8,6)→(3,6) / 65` | `20261003 / 5 / 车 (7,1)→(4,1) / 1370` |

对应六份原始流位于 `config/games/xiangqi/candidates/`，头内含固定种子、尝试号、题型、FEN、证明标记、摆子与主变化。两步题的原生证明覆盖所有黑方应手；Conda 审核也独立检查唯一首着、无一步捷径、镜像与已发布包去重。审核器新增多文件模式，旧 5 道与本批 6 道共 8 份流一起通过跨批左右镜像去重：11 个不同候选，仍为 `staged-not-published`。此批仅证明规则与结构，不证明棋题趣味性、难度分级或发布许可；仍须最终内容审定、正式原生/Android 资产与视觉验收后才能计入关卡量。当前正式包仍为 16 关。
