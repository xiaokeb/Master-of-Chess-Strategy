# 连续将军成杀：实现边界

依据 2020 竞赛规则第 24.2 条，杀的威胁可通过连续将军达成，不限下一着将死。现有重型循环分类仅用立即将死，故需要新增检查链证明；第 26.1.2 条的帅将应将例外和 Pikafish 明确胜负优先保持不变。

本轮实施：

1. 象棋 C++ 增加只读棋盘证明接口，结果区分 `proven`、`refuted`、`inconclusive`。只枚举合法将军和全部合法应将，困毙不冒充将死。回到本链同一棋盘/行棋方的分支不能当作将死证明。
2. 检查链采用明确节点与深度上限；到达任一上限必须保留未知，不能把“范围内未找到”当作“没有杀”。不修改第三方引擎，也不作为正式 AI 替代品。
3. 保留原有立即杀识别。新修订只在走后被证明成立、走前被完整反驳时才扩展连续杀攻击性质；走前未知或已有同类威胁不新增判负依据。普通走子不执行此重型求解，仅在既有三次循环分析调用。旧 v3 不启用新扩展。
4. 先验收一着将死、两次连续将军、困毙/非连续静着、全防守、预算耗尽、红黑对照与不变状态；再验证循环裁定、恢复/悔棋、必要 JNI 和 APK 集成。只完成求解器不代表整个职业棋例系统已验收。

文件：象棋公开头 `include/mocs/engine/chinese_chess.hpp`、专属实现/测试 `games/xiangqi/checking_mate_proof.cpp` 与 `checking_mate_test.cpp`。统筹串行持有主/测试 CMake 窗口，仅追加这两个象棋源目标；不修改其他棋种文件、Kotlin 公共接口或 JNI 注册。实际节点证据完成后另写测试报告。
