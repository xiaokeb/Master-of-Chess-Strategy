## G1：有限诊断提案

提议固定四个**已经曝光且可指认来源**的真实位置：旧训练suite1有序第1、2局，以及已发布qsearch专项的两个原始FEN（标准初始局面、受将军应将诊断局面）。前两局从旧合法四步线路重放，不仅导入孤立棋盘；后两局保持专项原始FEN。G0先无搜索验证四位置在正式规则层的导入、合法根和非终局；不能假设专项的底层FEN夹具已经自动变成adapter可用局面。任何输入兼容问题须在首次搜索前修正提案，不在看到结果后换位置。不得从异常53局抽取位置，亦不得按诊断搜索结果追加更有利位置。

使用当前四个生产profile，不生成新候选卡；六字段顺序仍为depth／nodes／movetime_ms／MultiPV／偏差百分比／分差窗口：

| 档位 | 已有生产值（只用于拟议诊断） |
| --- | --- |
| 简单 | `2/2000/250/8/75/250` |
| 中等 | `5/12000/500/4/20/80` |
| 困难 | `10/80000/900/1/0/0` |
| 大师 | `0/0/1200/1/0/0` |

32次=4位置×4档×冷／热各1次。每个位置／档位使用一个新专属子进程，共16个；同进程第一次完整choose为冷调用，随后在同一权威局面调用一次为热调用，不在两次之间清表。使用既有诊断选着seed20260926；这不是未来保留集采样seed。按位置、档位、冷／热固定顺序执行，线程／Hash记录真实既有默认值（当前源为Threads1／Hash16MiB），不通过额外线程扩样。

每次保存请求身份、完整历史端点、权威合法根摘要、原始返回着、前后序列化字节及单调时钟。返回着必须在权威合法根内，choose不得改变局面／历史；单次拒绝、无着或非零退出不记为输／和棋。初始化、清表、历史回放等同样可能耗时，不能只检查movetime字段。

**观测边界：现有adapter不暴露NNUE加载或实际go／join时点。** 第一版只记录process_started／request_started／request_returned与冷／热完整choose耗时；冷减热不是实测初始化时间。不得把request_started冒充Pikafish实际go、或声称已经分离纯搜索与初始化。如后续确需内部阶段观测，先另审专属端口与源身份，不能用虚构时间字段补齐。

门限提案：热调用超过2秒记产品响应目标风险并停止进入下一大阶段；单次完整choose到10秒仍未返回记运行异常。两者测量区间不同于旧专项go→join容差，冷调用另列，不把冷启动延迟删掉。**是否允许在10秒结束本轮自有诊断子进程，必须在未来起跑协议明确审核；本计划没有终止权限。** 未批准自动终止时只发告警、保留锁与原进程，不启动下一请求。任何取消只针对新协议创建并核对身份的子进程，绝不查杀旧评测、App或其他棋种进程；终止ADB客户端不证明远端Native已结束。

曝光账本必须记录诊断初态、输入历史全部中间位置，以及日后任何真正搜索过或据以选择参数的位置；只记录不等于允许读取异常53局。114基线使用四半回合／全子力规范，两个专项FEN并非都在此采样域：新账本需区分四步基线、域外诊断及中间历史，并对board／side左右镜像作通用交叉检查，不能为凑114条而漏掉域外来源。

## G2：有限新训练与选卡

本轮不实例化新卡值。下一无搜索编码节点须先形成完整数值表，每卡四档、每档六字段，校验后封存；不能把运行时自由参数留给runner。

建议保留三卡的共享结构：卡0用E0/M0，卡1用E1/M0，卡2用E1/M1；困难／大师在三卡中相同，仍以现生产`10/80000/900/1/0/0`与`0/0/1200/1/0/0`为锚点。这只是去重结构，不是已生成候选卡。只在简单／中等的深度、节点、候选与受控偏差上提出有限假设，不通过降低大师、非法走法或延长到产品目标之外制造梯度；简单“新手”定位不能由相邻引擎分数替代。

作业固定为M0-hard、M1-hard、E0-M0、E1-M0、E1-M1、hard-master：2+3+1=6唯一作业，每份旧suite1六开局双向12局，合计72局、最多43200次搜索。三卡结构不能在实现后变成9份唯一作业。所有作业采用新搜索／执行器身份、规则4/1、600搜索半回合、eligible-only、adaptive-rule60-window；缓存每局清理、档位切换遵循真实adapter，不混用前卡缓存。旧训练seed可作为明确已曝光训练常量复用，不充当新未见集seed。

只在六份全部退出0、config＋12有序game＋summary、无上限未完且回放通过后排名；任一缺失、超限、身份漂移或辅助进度损坏停止后续。全部卡各强侧含和棋得分须大于0.5才具候选资格；按距0.70最大绝对差、总距离、实际总请求毫秒、事前注册顺序取最小。时间字段测量区间须各报告一致；冷／热不能混成“纯搜索”排序。相同pair/profile报告只引用一次，不追加第七作业；无合格卡则本轮不选。

唯一selection必须绑定全部六份原始报告／exit／audit／finished与原始数值表SHA，并从同一已核bytes重算，不凭卡名或只信selection自报。所有结果继续`production_changed=false`、`strength_accepted=false`。若以后要新一轮网格，先做独立预算与曝光处理，不能自动无限调参。

## G3：新未见集与一次性注册

卡值、选卡结果、训练规则及曝光账本封存后，才在未来操作中选择一个未使用的64位采样seed，**仅一次**，先封存再生成。本计划没有给出该数值。生成器沿用项目自编红／黑各11首着池、标准MT19937-64及四半回合合法非终局红先设计；最多100000次尝试，按生成顺序接受48个，不用引擎评价筛选、不足不换seed。

排除集合至少含既有66+旧holdout48共114个镜像类，还要并入本次诊断／训练／选卡实际曝光；训练全部中间局面也进入有来源的账本，重叠去重但不抹除来源。按候选所在采样域做精确及左右镜像排除，域外位置仍保留。旧48份全部已曝光，任何一条都不能因旧后续pair未完成而重新称未见。

新Native规则生成器与独立Python标准MT／拒绝抽样实现必须对同一新seed逐项同序一致；实际48份FEN、四步线路、接受次序、拒绝原因计数、有序FEN摘要、原始流和排除账本SHA均封存。48×4=192步真实规则与独立棋盘回放不可省。生成只用规则不搜索；代码审阅和完整回放不算搜索曝光，凡用搜索评分或人工因内容挑换则退役该集，不能删掉条目继续称独立。

CreateNew注册新的协议、根目录、远端名、运行器／审核器、实际Native构建、唯一卡、开局／曝光／seed和统计方法。注册不启动ADB或搜索；空目录或部分注册失败保留，不覆盖修复。公开名称不能与旧v1或当前只准入的协议互换。

## G4：单次运行、监控与完整审核

- 顺序easy-medium、medium-hard、hard-master；每组48开局双向96局，最多288局／172800次搜索，单局600搜索半回合不含四步开局。该上限只在choose返回后推进，不冒充同步调用超时器。
- 每次只能消费下一未存在槽；前组须完整后验、原始报告SHA、exit0与finished绑定且无删失。空槽、开始、失败、中断均消费，不自动重试／续跑／补局／跳槽。不依据已经看到的新holdout结果换卡再跑同集。
- 执行通道保留已验证的`adb shell -T`双流及远端退出码；源码／库／ELF／NNUE／设备身份在部署和前后验核实。进程创建、原生就绪、每局每步request_started／returned和最终退出分开记录，sidecar独立于严格比赛JSONL；不能拿只有config或宿主活跃判断搜索健康。
- sidecar逐记录携带协议／run／pair／game／ply和单调序号；写入要有界且明确flush，断尾保留。进度频率可按每次请求开始／结束固定，不输出未授权额外搜索或候选排名；侧写失败不静默忽略。其无搜索／无终态性质与正式summary区分。
- 正常结束必须完整核config、96个有序颜色配对、参数和原始summary算术，再逐着独立普通棋盘回放、自然限着资格元数据和有限耗时验证。审核仍不声称独立重判全部2020复杂裁定或证明旧异常根因。
- 观察超时、非零退出、stderr异常、sidecar失败、源漂移、删失或审核失败均保留原始stdout／stderr／started／PID／exit／audit／锁；无finished，不发胜负或积分，不进入下一pair。进程退出与设备资源释放须独立核实；只允许尚未创建child或完整成功后自动释放对应窗口。
- G1的10秒提案不自动扩展为比赛kill策略。G4若要自动停止，须在首次运行前单独固定所有阈值、超时测量区间、进程归属及整槽中断处置，再由统筹审执行权限；不能运行后看到慢局才新增门限。

## 统计与未来产品决策

完整报告同时给W/L/D、W/N、`(W+D/2)/N`及决定性局条件胜率，并明确三者不同；训练排名沿用已声明的含和棋得分目标0.70，不把条件胜率当产品通过。任一未完时，不给完整样本单点得分；固定N上的得分删失上下界单列，不称置信区间。

响应统计按档位列真实完整choose请求次数、冷调用与后续调用的mean／p95／max及超过2秒次数；p95建议固定nearest-rank，不能事后换分位算法。冷启动、超时和异常不得静默丢样本：未返回请求只给已等待时长下界，不能填成10秒“实际完成耗时”，也不能构造完整延时分布。该数据为模拟器端到端观察，不冒充纯go→join、全设备上界或ARM64真机性能。

建议事前固定以48个开局为簇、每簇包含双向两局的配对分析：报告逐开局得分与双向差；如实现bootstrap，建议10000次、95%百分位区间，并在结果前固定独立统计seed和算法。不能把两种颜色、每着或多次请求当独立样本扩大N；48簇也不保证足够窄的验收置信度。统计seed不是采样seed，二者未来分别封存，本轮均未生成。

需要未来最终验收决定的真实缺口是：“胜率7:3”究竟以W/N还是含和棋得分解释，允许的数值窗、三pair同时满足要求及区间跨窗处理。现有正式PRD／task-levels没有答案，不在看到结果后选有利口径。此缺口**不阻断G0无搜索编码或G1诊断规划**；应在新holdout首次结果产生前冻结产品判据，未定时只允许报告数据、保持`strength_accepted=false`，不能宣布梯度达标。
