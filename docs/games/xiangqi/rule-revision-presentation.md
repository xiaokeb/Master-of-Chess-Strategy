# 对局规则修订提示与字节往返

依据 MOCX v4 已确认的规则隔离：旧局不追溯改判，新开局使用连续杀证明修订。用户需要在继续旧局时明确看到差异，而不是仅在开发文档中记录。

实施边界：

1. `engine-api` 仅新增象棋专属可选元数据能力及规则修订枚举，不改泛型 RuleEngine、动作码、胜负码或 JNI 注册。Native 门面从已持有的原生存档读取修订，核布局/CRC并缓存；成功恢复和重开才失效，失败恢复不得把旧提示换成新提示。
2. 对局状态保留可空修订，未提供该能力的测试/诊断引擎不凭空标为新规则。正式对局控制栏显示简短修订标题和说明；旧局明确保留原裁定，新修订明确有界证明而非专业图谱全覆盖。
3. 现有会话、备份和棋谱继续携带不透明原生字节。不改 Room schema、不修改旧终局/成绩；补 v3、v4.0、v4.1 的字节逐项往返和防御性复制测试。
4. 定向门面/状态/业务 JVM 测试，真实 JNI 元数据专项、双 ABI APK/Lint，再以无 Room 的 Debug QA 入口查看正式控件的新旧提示并实走循环。QA 不写成绩、不豁免被国标麻将导入阻断的正式 App AndroidTest，Release 不含入口。

统筹串行编辑窗口包含象棋 API 新能力、Native Kotlin 门面及测试、象棋 UiState/ViewModel、`MasterOfChessStrategyApp.kt` 的象棋控制栏、专属字符串、Debug Manifest/QA 入口及专属业务测试。其他棋种、导航、数据库和第三方依赖不改。测试事实完成后另写报告；真实 Room 恢复/已结算旧记录仍需正式 App 仪器测试，不以 JVM 内存 DAO 冒充。

续接：国标麻将专属导入修复已由统筹复编通过。追加象棋专属 App 仪器测试：v3/v4.0/v4.1 的进行中局面经实际 Room 关闭重开、ViewModel 实走到终局、再恢复/显式重开；已结算人机局保存实际棋谱和成绩账本，恢复不得改判或重复写入。使用独立 UUID 测试数据库，只删除本测试创建的数据库，不清空正式应用数据。构建和设备仍串行；新局/旧局视觉、大字体及返回首页另记录。
