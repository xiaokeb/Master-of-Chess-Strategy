# 老虎吃羊棋规则状态机

更新时间：2026-10-12

规则决定以 `docs/development/coordination-decisions-2026-09-30.md` 的老虎吃羊棋条目为准；棋盘几何与初始落点见本目录的 `geometry.md`。旧需求中“相邻空位的羊”和“开局先摆满”已由较新决定替代。

## 一局的阶段

1. **虎开局移羊**：中央环已有 8 羊、另有 14 羊待摆，双虎在两侧山顶。虎指定移去环上 1 羊。此后盘上 7 羊、待摆 14 羊、已被移去 1 羊，轮到羊。
2. **交替摆羊**：羊每回合在任一空落点摆 1 羊，虎下一回合沿正交印制线走 1 步或跳吃。虎跳吃完成后才轮到羊。待摆数减至 0 后，羊以后每回合沿任一印制线走 1 步。
3. **虎跳吃链**：虎沿正交印制线越过紧邻的 1 羊，落到该羊后方同一直线的下一空落点；被越过的羊立即移除。若落地后还有跳吃，虎可换向继续，也可结束回合。连跳时只允许同一虎继续；本链起点和各落点都记录在禁重访集合中。没有后续跳吃时自动结束回合。
4. **终局**：盘上羊加待摆羊少于 8，只虎获胜；两虎均无普通走步或跳吃时羊获胜。先按存羊数量判断，再检查虎的全部普通走步和跳吃。羊摆放期间必须把待摆羊计入存羊数。
5. **羊方无步**：全部待摆羊入盘、轮到羊且无任何合法沿线一步时，唯一棋盘动作是强制停着，下一回合由虎行动。仍按上述两类目标裁定；羊无步本身不另判虎胜。有合法步、待摆羊未用完、虎回合或连跳中均不能停着。

每个合法动作记录一份动作前状态，悔棋逐动作恢复棋盘、待摆数、行棋方、连跳链和终局。存档写出 `MOCT` 版本 2、棋盘拓扑版本 1、起始局面、动作序列和校验和；v2在动作表尾追加 `pass_goat=6`，0–5保持不变。可读取v1的合法0–5动作历史，禁止以v1包装新停着动作，未知版本拒绝。恢复时从起始局面逐动作重放；非法动作、版本或校验失败时拒绝，原对局保持不变。自定义起始局面只供规则测试和后续内容校验，必须维持“盘上羊＋待摆羊＋已移去羊＝22”、恰好 2 虎，不能直接注入未验证的连跳链。

羊无步是项目规则未写明的行动例外，本次据文献数字实现补齐，并非声称存在统一地方竞赛条文。[Winther的B型记录](https://mats-winther.github.io/bg/asiantiger.htm)与[Ludii的双虎规则](https://ludii.games/details.php?keyword=Rimau-Rimau+(Two+Tigers))均以围困双虎及减少羊为目标；后者的[原始规则文件](https://ludii.games/lud/games/Rimau-Rimau%20%28Two%20Tigers%29.lud)只在虎无步或羊全被移除时终局。[Ludii Core Game.java](https://github.com/Ludeme/Ludii/blob/master/Core/src/game/Game.java)为无合法动作的行动方提供强制停着。项目保留用户确认的不足8羊阈值、正交虎步、单羊跳吃及自愿连跳，仅采用这个无步处理；不混入23羊或虎重定位。来源核对日期2026-10-12。

## 本棋种接口与公共集成申请

规则层 `TigerGoatGame` 提供 `legal_actions()`、`apply()`、`undo()`、`reset()`、`serialize()` 和 `restore()`；动作有码值与点号，合法性由原生状态机裁定。对局 UI 需要每个落点的棋子、当前阶段、行棋方、待摆数、已移去数、连跳链和终局。原生 JNI 应使用按棋种隔离的进程内句柄，不暴露指针；释放、错误句柄和跨棋种句柄访问必须拒绝。

需统筹分配以下共享窗口：`engine-native/src/main/cpp/CMakeLists.txt` 和 `tests/CMakeLists.txt` 注册正式源文件与运行测试；JNI 注册与 `NativeBindings.kt`；`engine-api` 动作契约；`MasterOfChessStrategyApp.kt` 导航、首页入口；Room 活动会话与备份格式；Gradle 和 AVD。专属代码独立开发和验证后再领取各窗口，不把仅编译当作可玩验收。
