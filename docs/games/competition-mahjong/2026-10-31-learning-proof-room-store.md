# 国标麻将学习证明事务存储切片

本节点衔接[独立学习确认模型](2026-10-31-learning-proof-model.md)，新增专属Room行、DAO与事务Store。尚未注册到公共数据库、备份或正式教程页面；生产资格读取仍未切换。本节点不分配schema版本。

## 专属行和有界读取

`competition_mahjong_learning_proof` 只有 `singletonId INTEGER PRIMARY KEY` 与 `proof BLOB NOT NULL`，有效键为0。MCLP已承载独立格式/教材版本和连续章收据，不额外保存完成计数、时间或卡表。Row对象不在构造时拒绝坏值，使读取端能够保留并报告已有损坏数据。

DAO首先只取至多两条主键和 `length(proof)` 元数据，不直接装载BLOB。只有一条键0、长度8～4096字节的记录才进入第二次查询；该查询自身带长度条件，并用 `substr` 限制返回容量。Store再次核对返回长度并调用既有MCLP解码。两次读取位于同一Room事务。

没有专属行返回 `Ready(empty)`，不创建空记录。未知键、多行、超限、缺失或不匹配的载荷，以及MCLP坏格式/未知版本均返回 `Incompatible`，不删除、不覆盖。真实数据库I/O错误和取消继续向调用方抛出，不伪装为空进度。

## 章确认事务

`RoomCompetitionMahjongLearningProofStore(database: RoomDatabase, dao)` 接受宿主数据库与专属DAO，无 `MocsDatabase` 依赖或未来accessor假设。调用方必须保证DAO属于所传入的同一数据库。生产构造使用 `database.withTransaction`；内部注入事务执行器仅供JVM测试。

一次确认按以下顺序执行：

1. 在事务内重新读取并校验当前事实，禁止使用页面之前加载的计数覆盖数据库。
2. 调用纯模型 `confirm(request)`。相同请求返回原事实；跳章、重复ID或修改已完成章的请求转换为I/O错误，保留原数据。
3. 只有新增事实时才写键0。完全相同的重试不重写原时间或收据。
4. 在同一事务再次读取、解码并比较完整MCLP字节。读回缺失、损坏或内容不同即抛错，让Room回滚；事务成功结束才返回保存后的事实。

调用方创建一次请求UUID和确认时间，失败及确认丢失后重试同一请求。Store不自行补时间、生成请求、转换旧共享四步进度或授予胜场。取消检查位于读取前、写入后与读回后，提交前取消由事务回滚；提交后调用方丢失确认时仍可幂等重试。

## 调用者屏障与后续集成

本Store只保证同一数据库事务内的读取与确认，不实现写者归属、跨整库恢复代次或并行备份链。整库替换前，宿主必须先禁止旧控制器接受工作、等待所有已接受的读写完成，再执行恢复；恢复后的旧Store不能继续被调用。现有 `LocalDataWriterRegistry` / `LocalDataWriterRetirement` 可承担页面停写和排空接入。若未来允许绕过页面屏障直接调用恢复仓库，统筹需在同一集成节点补齐相应固定代次门禁。

后续统筹需统一注册实体、DAO、迁移和备份库存，接入独立备份扩展并更新整库清空路径，再切换Controller及正式页面。旧 `tutorial_progress` 只保留历史，无论其完成计数是多少都不能产生专属收据。新表启用但尚未纳入备份时，不得宣称学习持久化和恢复功能已完整开放。
