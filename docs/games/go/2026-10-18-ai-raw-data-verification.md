## 真实失败与修复

早期混合工作区设备 r2 的延迟外键专项曾失败：捕获 COMMIT 外键异常后，同连接仍可读到未提交孤父行。这不等于数据已持久提交。日志保留于 `.build/go-ai-20261018/device-3e69414c352d43bca7fc2950a8076af3/`，不能计为通过。

SQLite 明确说明延迟约束失败的 COMMIT 不结束原事务；见 [外键](https://www.sqlite.org/foreignkeys.html)、[事务](https://www.sqlite.org/lang_transaction.html)。本机 Android 37.0 SDK `SQLiteSession.java` 的 `endTransactionUnchecked` 先弹逻辑事务栈，COMMIT 的 finally 记录结束/释放连接，未在该路径补 ROLLBACK；源 SHA256 `b2f382f8d122276ef34e9c9b9f14ebcfcad4568605a884ee071e3f120c612d3d`。这是本地源及当前设备观察，不泛化所有 Android 实现。

修复不删除外键、不改为级联：Store 和全量恢复两处写入口，均在同一事务成功标记前查询最终父引用，孤父在事务体中抛错，从正常异常路径回滚。仍允许事务内先子后父。结构守卫不替代 Native 准入或全图来源检查。最终候选的真实 SQL 注入测试验证设置/四封口/AI 行一起回滚，随后同连接还能完成合法事务。
