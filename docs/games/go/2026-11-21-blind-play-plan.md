# 围棋盲棋实施

正式需求的盲棋玩法采用棋子背面展示。新局设置提供选择，行棋时黑白棋子显示同一颜色背面，保留空点、最后落点和合法操作。无障碍描述也隐藏棋子颜色。进入数子或终局后恢复黑白颜色，便于核对死子与复盘。

模式随对局配置持久化。GAI1 v8 记录盲棋标记及可选时钟，普通无时钟、带时钟局继续各自编码。续局、重开、指定开局替换、自动接管、归档和备份均保留模式。Room 使用既有原始封装列，暂无 schema 变更。

成绩沿用既有来源规则。新建标准真人局使用原有创建证明；自动、让子与指定开局仍按原规则处理。初始证明与终局配置必须一致，不能在既有赛事中改写模式取得成绩。

## 验证安排

- 定向回归封装、原生记录准入、创建证明、模式切换、重开、指定开局与自动续局。补充 v8 时钟组合及版本标记损坏负例。
- 从正式入口开启九路盲棋，由真实模型应手，检查屏幕和无障碍描述隐藏颜色。返回续局后核对模式、身份和原生记录，认输后显示黑白原色。
- 验证备份原始封装及 Room 准入，检查普通与 150% 字号的正式页面。完成构建、Lint、模拟器与视觉检查后按节点发布。

已通过 141 项定向 JVM 测试，NDK 30 双 ABI、Debug APK、测试 APK 与 Release 主清单均生成。Lint 0 错误、25 警告。Pixel 7 Pro 通过两档字号的生产对局用例，以及独立 Room 备份恢复用例，共 3 项。六张画面确认行棋及续局显示统一背面，认输后恢复黑白。大字号终局控制区可滚动，截图保留认输操作后的滚动位置。实体设备待验收。

## 独立进程恢复复验

Pixel 7 Pro 用两份独立 Room 存档加载正式棋盘组件，终止 QA 进程后使用新进程读取同一对局。两次均核对局面、盲棋标记、原生事件、检查点散列以及棋谱和归档数量。

| 场景 | 重启前后核对结果 |
| --- | --- |
| 行棋两手后 | 两枚棋子均显示背面，无障碍描述也隐藏棋色，最后落点保留。 |
| 双方虚着后协商死子 | 棋子恢复黑白，保留一枚待确认死子。黑方已确认，白方待确认，仍无棋谱和终局归档。 |

通过两项 JVM 测试和两项模拟器场景，核对四份无障碍树和四张截图。NDK 30 双 ABI、主包、仪器包和 Release 主清单构建通过，Lint 0 错误、25 警告。[进程复验证据](../../releases/manifests/v0.1.0-go-blind-process.1.json)

## 十九路长局复现

在 `MasterofChessStrategy` Conda 环境运行 [设备驱动](../../../tools/android/go/test-blind-long-game.py)。传入现有 SDK 的 `adb`、启动好的 Pixel 7 Pro 模拟器序列号、含 `build-receipt.json` 和两份 APK 的冻结候选目录，以及新的证据目录。驱动校验 APK 散列，在独立 Room 存档中从空盘启动第二局，使用正式对局页面与随应用加载的 KataGo。测试会核对中盘重启，双虚进入数子，双方确认后的终局重开，以及棋谱、归档和成长记录的数量。

本次运行保留首次启动写下的空盘收据。设备驱动先遇到收据尚未写入，随后遇到一次 ADB 超时。两次均沿用同一份种子存档。第 16 条事件从原 Room 检查点恢复，此后第 81 条事件按测试流程暂停并终止专用进程。中盘重启前后的棋局收据仅进程号不同，逐点核对了全部 361 个交叉点的无障碍描述和两张截图。

第 355 条事件双虚进入数子。棋盘及无障碍描述恢复黑白，双方依次确认空死子提议。第 357 条事件后页面显示白方获胜，达到连续局上限。终局再重开时结果、原生检查点和归档数量一致。直接只读核对 Room，棋谱、归档和投影各一份且共享同一记录 ID，无正式人机成长结果。

两项 JVM 测试通过，NDK 30 双 ABI、主包、仪器包和 Release 主清单构建通过，Lint 0 错误、25 警告。实测为模拟器简单档自动演局和默认字号，实体设备视觉与独立棋力验收另行跟踪。[长局证据](../../releases/manifests/v0.1.0-go-blind-long-game.1.json)
