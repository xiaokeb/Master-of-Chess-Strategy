# 正式 AI 设置与生产导航专项

新增 `GoAiProductionEntryInstrumentedTest` 六项设备测试源。它们未在本专属对话中编译或运行；正式构建、模拟器执行及视觉复核由统筹负责，不能沿用前驱节点的通过记录。

## 覆盖范围

1. 通过真正生产 App 的首页围棋入口进入 AI 设置，九课进度下新局与简单难度保持禁用，没有活动局／正式来源／AI owner。
2. 在隔离 Room 预置十课完成，经生产 App／NavHost 设置九路新局；使用未替换的 `GoAiAssetModelLoader` 和 `NativeGoSearchRuntime`。人落 `(0,0)` 后等待实际 NN 应答，重新以 Native 恢复两事件历史验证合法性；没有 Pass 脚本、搜索替身或后备合法走子器。返回后检查捕获 VM 的独立退休收据已成功，再恢复当前九路执黑局；选择十三路执白不影响“继续”。放弃弹窗取消后，完整 GAI 字节与正式来源数量保持不变。
3. 有效 UUID 但不存在活动局时，经真正 NavHost 的生产 play route 返回生产设置 route，无活动局／归档／正式来源／完成棋谱。
4. 含 NUL 的真正非法 GAI 身份拒绝并返回设置，不创建 AI VM；不把“非 UUID”旧身份误当非法。
5. 真实 `ActivityScenario.recreate()` 后，仍为同一 UUID 专属 DB、同一 AI VM 引用和同一对局；退休收据未结束、页面未关闭，随后真人落子仍得到真实 NN 合法应答。此项只证明 Activity 重建，不是杀进程或系统回收恢复。
6. 标准真人局在生产棋盘内显式重开 A→B，先断言 B 确实保存并绑定第二份正式来源，再 Activity 重建；页面仍为 B、同 VM 引用、未重复创建或退休 owner，不意外返回设置，再次真人落子获得真实 NN 应答。未用训练局替代此标准局验收。指定开局 A→B 的同类生命周期尚未测，不从重开结果推断通过。

缺失／非法入口同时检查无模型 loading 节点与无已注册 `GoAiMatchViewModel`。生产路由中的模型 loader 仅位于创建该 VM 的已有局分支；当前没有独立 loader 调用计数钩子，因此不虚构该计数或 Native 活跃 handle 数。实际 NN 测试不代表四档棋力或完整对局验收。

## 隔离、清退与证据

测试启动现有 Debug `GoLocalDataCheckActivity`，只使用其 UUID 专属数据库，不启动会读取主用户数据库的 MainActivity。首次进入 Go 前，在该测试库封口所有旧源并写入专属教程行，不读取或清空主用户数据库、AI 存档、SharedPreferences 或应用数据。生产模型仍使用已锁定资产及正常校验缓存，不手动删除或更换模型、许可或通知；正常 loader 的校验缓存准备不作为用户存档操作。

前四项替换初始内容后使用自有 `ViewModelStore` 承载真正 App／NavHost；第五、六项保留 Debug Activity 自己的生产内容和 Android 管理的自有 VMStore，按平台方式在重建中保留。该 Activity 保存并恢复专属 UUID DB 名，不会重建到主用户 DB；不在重建后强行挂另一个自建 store，以免默认恢复的 Root 已经先创建另一模型。清理先卸载 Composition，再在主线程捕获并启动所有已注册写者退休、清理自有及 Activity VMStore，最后等待独立资源收据与 scope 全部结束，才关闭和删除本测试库。清退失败时不继续关库假装成功。生产 AI 返回路径也显式断言退休收据已完成且未失败。

所有 UI／NN 等待都有 15 或 60 秒上限，清退为 60 秒；不使用固定长睡眠。当前设计仅六项测试源，未运行 Gradle、NDK、ADB、Git 或模拟器。截图保存于应用外部文件目录 `go-ai-production-entry-qa/<UUID>/`，每方法隔离；统筹可在 100%／150% 字体重复该专项，逐图查看设置、实际应答、退出后当前局、恢复及取消界面。尚未生成图片或宣称视觉通过。

第六项还会明确暴露标准进行中重开被旧正式创建门禁拒绝的前置缺口：如果未真正生成 B，测试先按生产 error 失败，而不是继续重建或假称 Route 身份问题已验证。统筹负责把显式重开与正式原子替换接通；数据专属冻结文件不由本测试切片修改。
