# 围棋正式来源与成长事务：设备测试计划

## 范围与当前状态

`GoRankedGrowthInstrumentedTest.kt` 新增 **15 个测试方法**，供统筹在 schema 18 与正式创建/完成事务接入后集成。**目前仅完成测试编写和 API 人工核对，未编译、未运行，不能作为通过或发布证据。** 本任务不执行 Gradle、ADB、Git，也不修改生产或公共文件。

每个方法创建独立 UUID 命名的磁盘 Room 数据库；`finally` 只关闭并删除本方法拥有的测试数据库。无全局应用清空、安装数据库访问、模型搜索、模拟胜场注入或用户文件改写。所有对局历史使用实际 `NativeGoEngine(9)`，由双虚与双方确认得出白方贴子胜；白方真人对应第二玩家。

## 验证清单

1. 九课拒绝正式创建，十课完成后 EASY 无胜场前置。
2. 创建事务末端失败与取消时，活动 GAI 与来源一起回滚；同连接重试成功。
3. 真正关闭并重开磁盘数据库后，来源版本、创建时间、规范 GAI 与活动局一致。
4. 真实白方胜：持久化终局及 reservation 后，完成幂等、收藏保留、重开后仍单条 outcome/marker/projection，统计一胜与 EASY 10 分。
5. 完成事务末端 I/O 失败时，棋谱/投影/outcome/marker 一并回滚，创建来源与首次原始归档保留可重试。
6. 完成事务取消时，同样回滚并可在同连接重试。
7. 未经正式创建的旧局，普通完成与显式回填均不补来源、不授成长。
8. 正式来源局随后自动参与，仍保存普通棋谱，但没有成长结算。
9. 即使已有正式创建来源，显式回填也不能签发 settlement。
10. 本机完成时间回拨早于创建，保留普通完成棋谱而不授成长。
11. 旧 GO ledger 各级 25 胜不参与可信统计或解锁；database-aware 普通 record(GO) 不能伪造胜场。
12. epoch 切换后旧 creator 不得写来源；新 creator 可正常创建。
13. 旧进行中活动局不能被替换，也不能以相同身份补发来源。
14. 旧终局只有持久 reservation 与已投影同时存在，才允许开启下一正式局。
15. 以 **45 局真实 Native 白方胜** 验证精确门槛：10 EASY → MEDIUM，15 MEDIUM → HARD，20 HARD → MASTER；每一档最后一胜前仍拒绝下一档。
