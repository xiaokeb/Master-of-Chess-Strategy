# 围棋棋谱与事件历史接口 v1

统筹共享接口；规则和 SGF 转换器仍由围棋专属对话维护。此切片不接文件选择器、导航、Room、奖励或公开题库。

## 调用与所有权

`GoRecordEngine : GoRuleEngine` 是新增可选能力，不要求现有规则测试替身改动。`NativeGoEngine` 在同一会话锁内提供：

- `exportSgf(): String`：标准 UTF-8 SGF 主线，含规格、贴子、固定让子和争议续弈先行方。
- `restoreSgf(text): RestoreResult`：规格须与此句柄一致；合法输入原子替换，拒绝不改变当前局。不是追加走子。
- `eventHistory(): List<GoAction>`：所有成功事件的独立快照，包括落子、虚着、死子标记、确认和续弈；悔棋删除最后一个事件，重置清空。

`NativeGoSgfImporter.importSgf(text)` 用真正的解析器依次尝试 9/13/19 路候选，而不是从注释里正则搜索 `SZ`。失败或异常关闭候选；成功的 `GoSgfImportResult.Imported.engine` 由调用者负责关闭。应用先校验候选并持久化，保存失败关闭候选、保留活动局；保存成功后替换会话、刷新 UI 并关闭旧句柄。不得重用旧局的待确认动作/候选版本。接口本身不修改用户文件或成绩。

## SGF 与完整存档的区别

沿用现行专属转换器：FF4/GM1、中国规则单主线、9/13/19、普通贴子 7.5 目或 0、固定 2–9 子让子与零普通贴子、`HA/AB/PL`；恢复续弈以独立 `PL` 节点记录。非法走子、变例、任意摆局和 `RE` 结果等当前不支持，原子拒绝。未知注释可能被忽略，导出不保证保留第三方注释。

SGF 不承载双方死子提议/确认、版本时钟、最终结算或成长成绩。已终局对局导出后再导入，末尾双虚至多恢复为待协商；不能直接计胜场、奖励或解锁。完整恢复及逐协商事件回放使用 MOCG v3 原始存档，不从 SGF 重建终局确认。

事件中落子/虚着没有额外棋色字段：普通开局黑先，固定让子白先；每次落子/虚着换手，`ResumePlay.firstPlayer` 显式设下一手，其他协商事件不换手。事件索引不等于落子步数，固定让子不是历史落子。最后落点可从当前事件快照逆序查最后 `Place`；悔棋后重新查询，不能使用旧缓存。

## JNI 协议与限制

文本走 `ByteArray` 标准 UTF-8，避免 JNI modified UTF-8 破坏补充平面字符。输入最多 **1,000,000 编码字节**；Kotlin 先限制字符数量再严格编码，孤立代理项/超限返回 `CORRUPTED_DATA`。Native 入口再次限制字节数。导出严格解码，不以替代字符吞掉损坏。关闭/错误棋种句柄抛状态异常。

事件帧为 `IntArray[version=1, count, (kind,a,b,c,d) × count]`，最多 16,386 事件（含原生预留最终确认），要求长度精确。kind=1 落子 `(x,y,0,0)`，2 虚着全零，3 标记死子 `(x,y,actor,0)`，4 确认 `(actor,revision,0,0)`，5 续弈 `(firstPlayer,0,0,0)`。解码严格检查坐标、棋色、非负版本及保留位；不把畸形帧转换为合法动作。

## 验收范围

新增纯 JVM 编解码 **10/10**、真实 JNI **4/4**（含三规格/24 让子组合、Unicode 注释、完整事件/终局区别、原子拒绝、关闭及跨棋种句柄），既有围棋 JNI 3/3 与象棋桥 6/6。ARM64 严格检查、双 ABI APK/仪器构建通过，Lint 0 错误/9 提醒；证据见 `../testing/2026-10-04-go-records-jni.md`。文件交换 UI、持久化替换、棋谱库及实体设备仍待专属接入，不能以接口验收替代。
