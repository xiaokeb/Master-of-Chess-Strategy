# 围棋搜索运行时接口 v1

## 目的与边界

本接口把围棋规则会话与 KataGo 搜索运行时分开：调用方提交一份不可变的 MOCG
快照，运行时只返回建议着法和诊断指标，不直接修改对局。公开结果只允许落子、停一手、
取消、忙或预算耗尽；数子标记、确认结果和恢复行棋仍由规则会话处理。

v1 使用锁定的 KataGo CPU/Eigen 模型
`b15c192-s1672170752-d466197061`。不存在随机、启发式或空网络降级；模型缺失、损坏、
型号不符或规则不受支持时必须失败。测试 APK 内的模型载体不等于生产 App 已完成模型分发。

## Kotlin 契约

- `NativeGoSearchRuntime(modelPath)`：在工作线程创建；路径必须是无 NUL 的 Android 绝对路径，
  长度不超过 4096 个 UTF-16 单元。
- `prepare(snapshot, budget)`：复制调用方字节并返回一次性 `GoSearchRequest`。快照为
  1..1,000,000 字节；最多同时保留 16 个尚未释放的请求。
- `GoSearchBudget`：访问数 1..512，时间 1..20,000 ms。
- `request.run()`：每个请求最多调用一次。成功结果的建议着法仍须由当前规则会话按版本和
  当前局面重新校验后才能应用。
- `request.cancel()` 与 `runtime.cancelAll()`：只发出取消信号，不等待推理锁；运行中的请求
  最终返回 `Cancelled`。
- `request.close()`：可重复调用；先取消，再等待本请求退出，最后释放原生句柄。
- `runtime.close()`：可重复调用；关闭新请求入口，取消并等待运行中的搜索；已经返回给调用方
  的请求仍应由调用方关闭。

调用者必须在后台线程创建、运行和关闭真实模型；界面线程不得承担模型加载或搜索。

## 原生所有权与并发

运行时句柄和请求句柄分别存入类型隔离的注册表。每次 JNI 调用在查找时取得
`shared_ptr` 强引用，因此另一线程释放表项不会让正在执行的调用悬空。全局注册表锁只保护
查找和移除，不在模型推理、取消等待或线程 join 期间持有。

同一请求的并发 `run` 只有一个调用可以消费请求；其他调用失败为生命周期错误。同一运行时
的搜索由专属搜索锁串行化，竞争请求可以返回 `Busy`。关闭流程不得在持有 Kotlin 或原生
生命周期互斥锁时执行网络推理。

## 输入与结果约束

- 只接受 9、13、19 路的有效 MOCG 快照及完整已接受历史。
- 只接受 `playing` 阶段；双停一手后的数子协商和已经确认的终局属于非法搜索参数，必须在
  进入 NN 前拒绝。
- 搜索在隔离恢复的候选会话上运行；输入字节和源规则会话不得被修改。
- 建议落子必须再次通过原生规则门禁；非法、非有限或超预算结果不得跨过 JNI。
- JNI 结果帧固定为 9 个有限 `Double`：版本、状态、动作、坐标、访问数、耗时、白胜率和
  白方目差。非着法状态不得夹带坐标或指标。

异常映射：无效参数或模型为 `IllegalArgumentException`；未知、已关闭或已消费句柄为
`IllegalStateException`；模型后端和其他不可恢复原生故障为 `RuntimeException`。

## 许可与发布门禁

KataGo 源码、模型网络、Eigen 及其他随包材料必须使用仓库锁定的版本、哈希和许可文件。
发布前必须通过来源清单、源码可得性、NOTICE/许可资产和生产 APK 实际内容核验。本接口与
测试结果不构成商用许可意见，也不扩大 `NOTICE.md` 与 `docs/legal/` 记录的许可范围。
