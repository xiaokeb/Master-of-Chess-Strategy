# 任务分级与进入条件

来源：项目文档.md 第三章。任务按依赖推进，不使用时间排期；每个阶段只在前置接口稳定后展开。

| 阶段 | 状态 | 当前说明 |
| --- | --- | --- |
| 一、基础前置 | 进行中 | 工程、Compose、NDK、JNI、Navigation 和 Room 完成；签名与后续业务数据格式按切片引入 |
| 二、核心引擎 | 进行中 | 中国象棋基础规则、JNI 与 Kotlin 调用闭环完成；历史判定和其他棋种后续按切片推进 |

## 一级任务

### 阶段一：基础前置

1. 环境：锁定 Android、NDK LLVM、CMake、JDK 和 Conda。
2. 工程：模块化 Android 工程、Compose、JNI、Navigation 和 Room。
3. 规范：编码、命名、注释、版本、序列化和内容格式。

进入阶段二的最低条件：构建可复现、离线权限通过、Kotlin/JNI/C++ 边界可连接。该最低条件已满足。

### 阶段二：核心引擎

1. 统一抽象：状态、动作、执行、撤销、终局、序列化和错误。
2. 规则引擎：中国象棋、围棋、国标麻将、兰州麻将、方棋、老虎吃羊。
3. AI 适配：许可证与移动端评估通过后，按棋种逐一接入。
4. 测试：合法动作、非法动作、边界、重复局面、序列化和回归。

执行顺序采用单棋种纵向切片：规则模型 → 最小合法走法 → JNI → Kotlin 调用 → 测试 → 再扩展规则。不同棋种不同时铺开。

### 阶段三：业务与玩法

1. 页面：首页、对局、残局、教程、棋谱、个人中心、设置。
2. 系统：对局管理、残局、成长、棋谱和教程解锁。
3. 扩展：限时、连胜、盲棋、自由摆局、棋力评测和自动演局。
4. 联调：页面、业务、持久化和引擎端到端验证。

### 阶段四：资源与优化

1. 残局：采集、许可、转换、校验、分级、压缩和索引。
2. 资源：棋盘、棋子、人物、图标、动画和音效。
3. 优化：性能、体积、功耗、稳定性和兼容性。
4. 交付：回归、压力、Release 签名、校验文件和用户文档。

## 任务完成定义

- 需求与边界写入正式文档。
- 代码与命名符合现有模块边界。
- 受影响模块测试通过，跨语言改动完成 NDK/JNI 编译验证。
- 设备依赖项明确区分“已编译”和“已运行”。
- 大节点更新进度、变更记录并提交；网络可用时推送远程。
