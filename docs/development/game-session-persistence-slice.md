# 对局自动保存与恢复纵切

## 目标

使用统一 Repository 和 Room 保存中国象棋本地双人活动对局，在应用重新进入对局时恢复最后一个已确认局面。

## 数据边界

- 数据库仅保存活动会话信封；规则合法性仍由 NativeChineseChessEngine.restore 判定。
- 信封版本与 MOCX 引擎格式版本分列保存，未知版本拒绝恢复。
- engineState 使用 BLOB，Repository 在保存和读取时均复制数组。
- 单个引擎状态限制为 64 KiB，防止损坏数据造成无界内存分配。
- 每个 GameType 最多一个活动会话，后续棋谱历史使用独立表。

## 时序

1. 对局目的地创建 ViewModel 和原生引擎。
2. ViewModel 异步读取活动快照；恢复完成前禁用走子、悔棋和重开。
3. 恢复成功后刷新不可变棋盘；不恢复原生撤销栈，因此悔棋从新走子重新计数。
4. 每次成功走子、悔棋和重开后生成快照。
5. 连续保存按修订号串行合并，旧快照不能覆盖较新局面。
6. 数据库、信封或 MOCX 校验失败时回退标准初始局面并给出可恢复提示。

## 版本

- Room schema：2；活动对局表结构仍为 schema 1 定义，schema 2 仅新增上次选择表。
- 活动会话信封：1。
- 中国象棋引擎格式：MOCX 2；MOCX 1 因缺少历史与 CRC 按不兼容快照安全回退。
- Room：2.8.5。
- KSP：2.3.12。
