# 兰州麻将正式入口实施计划

前置节点已发布：安全Host `4f6c0c5`，独立十课/备份 `9cd0639`。本计划按正式PRD的教程→简单、简单10胜→中等、中等15胜→困难、困难20胜→大师推进；不把本节点称作完整棋种完成。普通实现决定沿用既有授权，无需重新审批。

## 审查结论

实际首页与NavHost位于`ui/MasterOfChessStrategyApp.kt`，`navigation/AppNavigationModel.kt`仍把兰州麻将标为不可用。十课页面及规则/持久化已验证，但尚未连接正式菜单。当前Host.open优先加载活动局，并用存档难度覆盖请求；restart直接创建下一局，尚无独立教程资格检查。只禁用难度按钮会留下旧高难度续局后重开的旁路。

通用MatchOutcome的ID上限64、玩家席位0..1，不适合兰州69字符sessionId及四席。现有qualifiedMatchOutcomeRows只核验围棋来源，不能把game3旧通用行作为可信兰州胜场。完整动作历史准入证明规则状态可重放，尚不证明正式创建来源、难度解锁或首次终局结算。上述问题无需放宽公共契约解决。

## 按依赖执行

1. 新增专属EntryRepository及事实模型。生产构造只接受实际MocsDatabase，派生同DB gate/固定Owner；读取独立版本2十课、严格准入活动局和明确的“可信胜场来源尚未接入”状态。缺学习行表示未完成；坏行/失败保持错误，不能降为0课或0胜。聚合读取直接使用DAO及严格decoder，不在非重入gate内套调用已持gate的Repository。
2. 将新建与续局意图区分。菜单明确展示继续原局及其难度；新建存在活动局时返回冲突，不静默恢复或覆盖。先只开放十课完成后的简单新局；中/困/大师显示真实来源尚未接入，保留正式阈值说明，不伪称已统计0胜。旧高难度活动局仍可严格恢复原规则、席位和辅助用量，不追授资格或胜场。
3. 在Host实际创建和restart前重读资格，固定同Owner，并验证当前活动快照符合新建/替换意图。拒绝时保留原Native句柄与存档；资格检查放在关闭旧句柄之前。错误路由、恢复导航栈及直接VM调用不能绕过。退出/恢复仍等待writer退休；准入检查与后续保存分别检查epoch，恢复后旧写者不能补回。
4. 新增专属菜单、学习/难度/对局导航装配；VM绑定导航entry与epoch，注册同DB LocalDataWriterRegistry。学习返回重新读事实，不缓存旧资格。首页可用性仅在正式路由与错误返回闭合后开启。快捷进入/选择保存使用实际已实现范围，不能把历史选择当授权。
5. 冻结完整候选后执行受影响JVM、双ABI/Debug/AppTest/Manifest/Lint，以及真实Room/Native和正式导航模拟器验证。覆盖无教程、旧四步不能解锁、十课解锁简单、未知/坏数据不覆盖、直接创建/重开旁路、已有局显式续局、恢复退役、学习返回刷新及普通/150%画面。复用未改源码的既有证据，失败只重验受影响输入。
6. 通过后显式暂存本节点路径、全树导出核验，串行提交/推送、附注tag和源码预发布，更新四份统筹索引。其他棋种及象棋未发布WIP保持原样。
