# 中国象棋后台运行实施计划

状态：调度、共享会话前台服务、通知控制和受控唤醒锁已实现；模拟器短时熄屏链路已验证，深度休眠、冷启动和真机长期功耗仍需后续验收。

## 依据与差距

正式需求 2.2.3 要求后台挂机、熄屏不暂停、返回同步；性能章节要求后台降低资源消耗。
对局仍由导航项 ViewModel 唯一持有引擎和存档队列；控制器提供与其生命周期绑定的
借用租约，服务只观察运行需求，不另建棋局。持久化时间戳补算棋钟与服务维持 CPU
是两种不同能力；系统仍可终止进程或限制运行，不承诺无限保活。

## 分步实施

0. 已完成调度基础：所有象棋对局以当前页面生命周期报告可见性，不重建引擎。
   后台棋钟刷新间隔至少 1000 ms，自动演局的观看间隔至少 2000 ms；
   搜索难度/预算和用户速度设置不变。恢复可见时立即同步棋钟；每次延迟不会跨过
   当前超时截止点。终局、手动暂停、引擎关闭时取消棋钟任务，避免无效空转。
   详见 `../testing/2026-09-26-background-scheduling.md`。
1. 已完成会话注册与释放：界面与服务共享同一引擎、存档队列和终局回调；配置重建保留
   原 ViewModel。退出对局释放租约；异常重叠的新路由先停旧任务，旧令牌不能释放或停止新局。
2. 已接入可见前台服务，通知提供返回与停止；启动在可见界面中进行。
   采用与用途匹配的 `specialUse` 声明并描述离线棋局计算；不伪装媒体播放或定位。
3. 已接入部分唤醒锁：仅后台 AI、演局或待完成存档需要 CPU 时申请；每 30 秒检查进展，
   同一棋局/步数最多保有 60 秒预算，无进展不能无限续租。前台、人类思考、暂停、终局、
   失败和退出均释放；人类思考仍以时间戳补算棋钟，不持续占用 CPU。
4. 保留系统最终控制权：不自动申请电池优化豁免，不静默重启被用户停止的服务，
   不承诺强制停止/系统终止后仍运行。再次打开从最后一致存档恢复，不重复奖励或棋谱。
5. 已覆盖通知不可用时拒绝启用、短时熄屏新着、通知停止、正式 Activity 重建/通知返回、
   旧通知隔离及租约释放。继续验收强制 Doze、进程死亡后的冷启动、备份切换和真机长时
   功耗/性能；模拟器短时结果不能代替这些项目。

## 用户控制与权限

- Android 13+ 通知请求只由“开启后台挂机”按钮触发；拒绝后仍可前台下棋，提供系统通知设置入口。
- 已允许通知的新对局可自动启用；当前对局显式停止后不会因重新可见而自行开启。
- “停止挂机”不认输。自动演局暂停；在途搜索或存档在安全点收尾，恢复存档中不会抢写新状态。
  人机/双人的正式棋钟仍计时，停止服务不产生额外思考时间。
- 新增 `FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_SPECIAL_USE`、`WAKE_LOCK`、
  `POST_NOTIFICATIONS`；服务不导出，不新增网络权限，也不申请电池优化豁免。
- 通知 PendingIntent 显式指定组件且不可变；停止动作使用独立会话令牌，返回动作复用现有任务。
- 服务使用 `START_NOT_STICKY`，没有开机广播或自动重启机制。平台拒绝启动、异常销毁、超时会
  显示不可持续运行状态，不循环尝试启动；重新开启须由可见界面的用户动作触发。

## 平台依据（2026-09-26 核对）

- [前台服务概述](https://developer.android.com/develop/background-work/services/fgs)：持续工作必须对用户可感知。
- [服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types)：声明匹配类型及权限；specialUse 用途需要解释，商店上架另有审核，不代表已获准。
- [唤醒锁](https://developer.android.com/develop/background-work/background-tasks/awake/wakelock)：仅用于必要的持续工作，及时释放。
- [Doze 与待机](https://developer.android.com/training/monitoring-device-state/doze-standby)：系统休眠策略仍可能限制运行，不能承诺无限后台保活。

本节点不改 Pikafish 许可、NNUE 使用范围、自然限着口径或 AI 棋力参数。

## 当前实现边界

- 普通前后台切换保持现有会话、AI、棋谱及存档所有权；设置页覆盖对局时也采用后台节奏。
- 已经开始的单次观看等待允许完成，不取消并重复发起 AI；新安排的等待采用当前节奏。
- 本轮降低的是调度频率，不是 CPU 硬件频率，也没有声称已测得电量收益。
- Activity 停止和短时熄屏测试不等于强制 Doze、长期挂机或进程死亡测试。
- 服务核心验收见 `../testing/2026-09-26-background-service.md`；下一步继续上述稳定性验收，不能据此宣称象棋全部完成。
