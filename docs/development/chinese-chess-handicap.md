# 中国象棋让子对局

状态：功能已实现；模拟器专项结果见 `../testing/2026-09-26-handicap.md`，不替代真机验收。

对应正式需求 2.2.3 的“让子自定义”。在设置及象棋模式页提供入口，
独立于自由摆局，不以手工编辑任意局面替代专门的让子功能。

## 实施边界

- 从标准棋盘移除任一方的非将帅棋子，可逐个选择、恢复及重置；提供让一马/一车快捷选择。
- 红方先行，玩家身份沿用 AI 先手偏好；已保存的让子局保留原身份。
- 普通行棋规则保持不变；不推断或混入传统让子棋的额外特殊约定。
- 双方将帅不能被移除；无让子选择不能误开标准对局。开局前检查将帅照面、终局、合法着等原生规则。
- 独立模式 HANDICAP，复用既有难度解锁、辅助次数、计时、音效、提和、认输、重开和棋谱功能。
- 与已批准的自由摆局一致：记录棋谱，不写入排位胜负账本或触发正式难度解锁。
- 初始让子方案随会话保存，继续对局恢复当前进度，重开回到同一让子布局。
- 每次新建分配独立变体标识，防止相同让子方案的“新局”误恢复旧局；导航恢复不再分配新标识。
- 从对局设置进入让子配置会释放原对局 ViewModel 的任务，保留其数据库检查点；直到正式开启新局才替换活动存档，避免两局同时写入。
- 备份同时校验当前棋局和由让子方案重建的初始局面；不允许伪造将帅移除或任意摆局。

## 验收计划

1. 纯 Kotlin：选择/恢复、双方让子、将帅保护、方案规范编码、独立新局标识及难度锁定。
2. Native：合法让子开局可恢复且可行棋，非法或已终结方案拒绝。
3. 对局：玩家红/黑、AI 应答、整回合悔棋、重开/恢复和终局棋谱；无排位奖励。
4. UI：设置/模式入口、实际棋盘选择、真实 Pikafish 应答及完整返回链路。
5. 持久化：活动会话、快速进入、棋谱与备份往返，旧模式回归。
