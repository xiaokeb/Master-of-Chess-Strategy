# 多对话开发协调

本对话是统筹窗口：安排接口依赖、分配公共文件、汇总测试与远程提交状态，并将跨棋种冲突或规则歧义依次提交用户决定。棋种对话负责实际设计与编码；所有对话共享同一工作区，不使用 worktree。六个棋种均可立即启动专属工作，但启动不代表交付。

## 统一验收与文件边界

各棋种从 PRD 形成可玩功能清单，逐项记录实现、自动测试及模拟器操作证据，用于质量与剩余工作管理；不再计算跨棋种启动用的 80% 阶段线。代码存在但无法玩通、仅编译或未验证的项不计为已完成。内容数量、AI 棋力、真机音效/性能、发布许可与全量回归分别跟踪；某一棋种开始开发不代表其他棋种已经完成。

棋种专属新增文件使用明确的棋种命名及目录；测试与报告写入对应的 `docs/testing/` 文档。公共契约、JNI 注册、CMake、应用导航、数据库、通用字符串/图片、构建配置和 `docs/development/progress.md` 是共享文件，任何棋种对话拟修改前先在本对话登记范围并领取串行编辑窗口。Gradle、NDK 构建和 AVD 测试亦串行执行，避免共享输出和模拟器状态互相污染。Git 提交/推送由统筹对话串行组织；棋种对话不要批量暂存整个工作区或擅自切换分支。

每个棋种对话在 `docs/development/chat-status/` 下维护表中同名的状态文件，节点结束时写入完成的功能及文件、测试命令与结果、模拟器/视觉证据、剩余问题、涉及的公共文件；若节点已提交，再附提交哈希与远程状态。本统筹对话从这些文件和 Git 记录汇总进度，不假设能直接读取其他对话消息。遇到规则、授权、接口或文件冲突时，写明选项、依据、影响和推荐方案；受影响工作暂停，其他独立工作可继续。统筹对话按依赖顺序向用户提问，决定后同步到正式规则或架构文档。

## 新对话起始任务

在新对话中写明棋种标题，再使用以下任务说明（替换方括号内容）：

> 这是 MasterofChessStrategy 的【棋种】专属开发对话。先完整读取仓库根目录 `AGENTS.md`、`docs/development/chat-coordination.md`，再按需读取 `docs/requirements/` 中该棋种规则、PRD、页面交互、任务分级及现有进度。遵守不使用 Superpowers、不使用 worktree、NDK LLVM/Conda 环境、许可边界、测试和文档规则。立即开始本棋种正式设计与开发，不受其他棋种 80% 进度约束；只处理本棋种专属文件，公共文件改动先向统筹对话登记。按规则模型→最小合法操作→JNI/Kotlin→界面→模拟器与视觉测试的纵向切片推进。每个节点更新 `docs/development/chat-status/` 下的本棋种状态文件，报告证据、风险和待用户决定的问题。

中国象棋对话的首项任务：接手 `ChineseChessTutorialScreen.kt`、`strings.xml`、`ChineseChessTutorialDiagramTest.kt` 当前未提交的七类棋子图解改动；先检查 diff，完成定向 JVM/Lint/APK 和模拟器视觉回归，再更新象棋功能清单与剩余工作。不要覆盖现有未提交改动。
