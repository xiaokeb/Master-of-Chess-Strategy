# 中国象棋历史裁定核心

## 目标

在基础走法之外保存可撤销的完整局面历史，为三次循环、长将、杀着、直接与联合追捉、允许着法循环和 60 回合自然限着提供确定性裁定。

## 规则口径

采用中国象棋协会审定《象棋竞赛规则（2020 版）》：

- 第 23.1：双方着法循环反复三次形成重复局面。
- 第 23.5.1：单方长将判负。
- 第 24.6、24.8：拦属于闲，兑、献、拦、跟均在闲着范围。
- 第 24.2、24.3：杀与捉均需形成真实得子或杀棋威胁。
- 第 24.9–24.11：长将、长杀和长捉均以循环三次为基础；长捉可交替追捉一子或数子。
- 第 24.15–24.17：有根、假根与联合捉必须结合合法回吃和交换结果判断。
- 第 26.1.2：帅将应将时附带产生的杀、捉按闲处理；真正将军仍优先记录。
- 第 26.9：单方禁止着法应变，双方允许着法不变作和。
- 第 4.2.4：连续 60 回合未吃子符合自然限着和棋条件。

原始项目文档把“长拦等重复局面直接判进攻方负”作为简写，与上述正式条款冲突；引擎不采用该简写。

## 状态与裁定

1. position_history_ 保存每步后的棋盘和行棋方，使用完整状态比较，不以可能碰撞的哈希单独裁定。
2. MoveRecord 保存走子、被吃子、上一步计数与裁定结果、着法性质，支持裁定后悔棋。
3. 仅在完整局面第三次出现后执行重型战术分类，正常走子和 AI 搜索路径不承担交换递归成本。
4. Pikafish 的规则裁定作为长将和直接追捉基线；项目扩展层按 2020 规则补充即时杀着、联合追捉、跨位置棋子身份和第 26.9 的直接捉对联合捉边界。
5. Pikafish 的明确胜负优先；扩展层只补充其判和或无法解析的复杂局面，双方均为禁止着法且无强制变着方时判和。
6. 被追棋子以循环起点分配的稳定 ID 跟踪，棋子移动后仍可识别同一对象；循环内也允许交替追捉数个对象，不要求每着目标 ID 相同。
7. 吃后交换递归允许双方停止交换，并排除吃后对方可立即成杀的伪得子；将帅和兵卒自身的允许长捉不计为禁止着法。
8. 每个未吃子着使自然限着计数加一，吃子归零；达到 120 着即 60 回合时判和。
9. 已终局后引擎拒绝继续行棋；悔棋恢复此前计数与裁定。
10. 帅将从被将军局面应将时，若只是露出其他棋子的杀、捉，历史着法与三次循环分析均记为闲；实际直接将军仍记为将。

## 长捉边界

当前自动识别包含：

- 排除帅将、兵卒自身允许的长捉。
- 捕获必须是合法着且不造成己方自杀。
- 结合合法回吃、子力价值和后续同点交换计算直接或联合得子。
- 被钉住而不能合法回吃的棋子不作为真根。
- 过河兵卒可成为被捉对象；刚过河的下一着按规则例外处理。
- 只有本着新增的杀棋或得子威胁才进入该着的攻击性质。

本地杀着扩展当前识别下一着可立即将死的威胁；多对象交替追捉已有回归用例，但更长的连续将军成杀，以及暗根、假根、少根和复杂多对象职业裁判棋例仍需继续扩充。项目不把算法覆盖描述为替代人工裁判。

## MOCX 2

MOCX 2 保存：

- 魔数、格式版本、显式 GameType 和当前方。
- 自然限着计数、历史裁定结果和历史条数。
- 当前 90 点棋盘及可逆走子记录。
- 末尾 CRC32，任何负载单字节损坏均在解析前拒绝。
- 恢复时从重建的初始局面逐着复核走子合法性、被吃子、行棋方与自然限着计数；仅有正确 CRC32 但历史走法不可能的文件仍拒绝。

历史最多 4096 着，最大编码仍低于 App Repository 的 64 KiB 边界。MOCX 1 不含历史和校验和，按不兼容快照定向清理并从标准局面恢复，不做有损伪迁移。
