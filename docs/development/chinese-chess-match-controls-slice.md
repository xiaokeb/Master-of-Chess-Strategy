# 中国象棋对局控制纵切

## 目标

把悔棋配额、分级提示和认输从占位控件接入正式对局状态机，并确保异常退出后恢复到同一配额和终局状态。

## 难度策略

| 模式或难度 | 悔棋 | 提示 |
| --- | --- | --- |
| 本地双人 | 不限 | 不提供 AI 提示 |
| 简单人机 | 不限 | 标记当前全部可走棋子和合法落点 |
| 中等人机 | 每局 3 次 | 每局 3 次，后台计算当前最佳着 |
| 困难人机 | 每局 1 次 | 不提供 |
| 大师人机 | 不可悔棋 | 不提供 |

原始需求的难度汇总表把困难写作“每局 1 次悔棋/提示”，但同章对局交互规则明确写明“困难/大师无提示”。本实现采用更具体的交互规则：困难只保留一次悔棋，不开放提示。

提示只读取当前合法着，不执行走子。简单提示用蓝色标记全部合法着的起点和终点；中等提示在后台调用当前难度搜索，返回值必须仍属于当前合法着集合后才消耗次数。提示计算、AI 行棋或持久化期间均禁止棋盘、返回、设置和其他冲突操作。

## 状态与持久化

Room schema 6 为活动对局增加以下字段：

- acceptedMoveCount：已接受着数，用于恢复后安全开放悔棋。
- undoUseCount、hintUseCount：本局已消耗的辅助次数。
- resultOverrideCode：认输等应用层终局结果。

活动会话信封升级为版本 2。5→6 迁移保留引擎状态和会话 ID，并将旧快照计数初始化为 0；旧快照因此不会冒充可撤销历史。新快照与 MOCX 2 的可逆历史共同支持恢复后的配额判断。

## 认输与结算

- 认输按钮先显示确认对话框，确认后按当前行棋方负立即终局。
- 终局覆盖与稳定 match ID 一起保存；恢复时不会继续触发 AI 行棋。
- 人机认输进入既有幂等终局账本，重复恢复或重复操作不会重复结算。
- 认输后禁止悔棋和提示，重开会生成新 match ID 并重置所有配额。
