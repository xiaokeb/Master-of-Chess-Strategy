# 中国象棋残局节点

更新时间：2026-09-26

## 已实现

- 版本化离线残局包、严格解析器和 MOCX v2 自定义局面编码。
- 简单至大师四档章节、关内线性解锁、完成整档后解锁下一难度。
- 主线、主题、按本机日期稳定选择的每日残局和仅从已解锁关卡抽取的随机挑战。
- 指定步数内红方取胜的通关判定；耗尽玩家步数且未获胜立即判挑战失败，
  不再触发 AI 应答。
- Room schema 9 保存稳定关卡 ID、最佳玩家步数、首通星级/积分和完成时间。
  `INSERT IGNORE` 保证首通奖励只发一次，重复挑战只允许改善最佳步数。
- 首页汇总对局成长与残局奖励；终局继续进入棋谱库并标记为残局棋谱。
- 模式页、快速进入、目录、关卡路由、残局目标提示、音效和 Android Studio
  Debug 预览已接通。

## 内容与法律边界

内置 v5 为项目自编的 16 关功能种子包，覆盖四档难度并用于验证完整业务链，
不冒充最终 9000+ 内容库。种子包声明 GPL-3.0-or-later，未复制外部棋谱注释
或来源不明的残局数据。未来扩充必须按
`config/schemas/chinese-chess-endgame-pack-v5.md` 保存当前内容格式；
`content/manifests/chinese-chess-endgames-v5.md` 保存逐批许可证据。

残局对局仍通过同一个中国象棋规则引擎验证合法着；大师难度继续调用已固定
版本的 Pikafish 和 NNUE。Pikafish 程序、对应源码、GPL 文本、修改记录及
NNUE 独立使用限制沿用项目现有发布门禁，本节点未放宽任何许可边界。

## 测试边界

JVM 测试覆盖格式拒绝、CRC32、解锁链、每日稳定性、随机候选、首通幂等、
最佳步数和对局限步结算。实际 APK 资产验证五关多解演示、九关唯一一步杀与
两关两步强制胜；后者穷举黑方所有应手，不以单条主变化代替证明。
离线原生证明器另有独立遍历、预算耗尽和困毙回归；Conda 检查结构、重复棋盘、
明显不可达局面及增量发布时旧内容保持不变。

2026-09-25 起已有 Pixel_7_Pro x86_64 AVD，可在模拟器运行 Compose、Room、
JNI 和 NDK C++ 测试；结果以当次测试报告为准。此前节点记录的“无设备”
仅描述当时环境，不代表现状。v1 三关错误局面已在 v2 修正，关卡 ID 和
既有通关进度保持兼容；旧活动会话因版本变体不匹配而从当前局面重开。
旧五关标为多解演示；新增五关各有且仅有一着将军取胜，均已在 AVD
通过实际发布资产与原生规则测试。新增关卡属于可选奖励支线，
不改变旧主线完成后解锁下一难度的条件。v4 还更正大师奖励关一枚红兵
原在起始行后方的错误位置，v3 活动残局从正确局面重开。
