# MOCX v4 规则版本封装

状态：连续杀接入开发中；最终行为与设备证据另写专项报告，不以 schema 代替验收。

v2/v3 的棋盘和历史记录布局不变：12 字节头、90 字节棋盘、每步 11 字节；v3 增加的申请数（小端 u16）及每项 3 字节自然限着申请事件也原样保留。v4 仅把头第 4 字节设为 4，并在申请事件之后、CRC32 之前增加 **1 字节规则修订号**；CRC 覆盖该修订号。

- 修订 `0`：原 v3 的循环裁定，不启用连续杀扩展。旧 v3 的进行中及已终局记录均固定于此裁定，继续保存 v3；v4 修订 0 继续保存 v4，不静默降级。
- 修订 `1`：保留原裁定/Pikafish 明确胜负优先，新增“走后连续杀已证明且走前已完整反驳”的循环攻击分类，深度/节点未知不构成新增判负。新开标准局和无历史的 v2 摆局写 v4 修订 1。
- 其他修订：返回 `unsupported`，不替换当前引擎状态，不以现有规则假读未知修订。
- v2 维持现有自动限着旧值重算逻辑；v3 保存终局仍须与可信历史重放严格一致，不放宽校验。
- 旧记录与 Room 已提交成绩不重写；本切片不升级用户数据，不更改共享数据库 schema。

读取次序：完整长度及 CRC → 头/棋种/状态编码 → 历史与申请表长度 → 修订号支持范围 → 原有合法历史重放与终局一致性。篡改修订号后即使重算 CRC，也不能被当成已支持规则。

应用的精彩局自动收藏仅在已支持的 v4 修订 0/1、长度和 CRC 都有效时解析子力，避免格式更新时静默丢失自动收藏；该解析器不替代原生历史合法性验证。其他备份、活动会话与棋谱仍携带不透明原生字节，本轮不改其外层版本。

v2 带历史记录保持既有 v2→v3 自然限着重算流程及旧循环裁定，不向已走历史追溯新连续杀；v2 无历史摆局按新修订开始。`reset()` 是明确的新开局界点，切换到 v4 修订 1；悔棋不改变存档规则修订。失败恢复原子保持原棋局与其修订。

真实正例：红炮 `(3,3)→(4,3)` 为非一步杀的连续杀，将 `(4,1)→(3,1)` 后炮退回构成将军，将退回复原棋盘；旧循环判和，新修订判进攻方负。需覆盖红黑对照、旧已终局/进行中/悔棋、原申请事件及 JNI/收藏解析。后续界面应说明旧局兼容规则，不能把核心格式完成冒充业务全链路验收。
